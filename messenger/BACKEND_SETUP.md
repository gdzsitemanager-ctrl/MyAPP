# FRONTLINE Messenger — подготовка backend и APK

## Что добавлено
- Адаптивный тёмный UI: messenger/index.html.
- Отдельная Android WebView-оболочка: messengerapp/, package com.frontline.messenger.
- SQL-основа Supabase: backend/supabase-schema.sql.

## Честный статус
UI пока демонстрационный. SQL и Android-оболочка не подключают сервер автоматически. Для настоящей регистрации, входа, SMS-кодов и обмена сообщениями требуется Supabase-проект, клиентская интеграция и настройки провайдера. Не храните пароль владельца или service-role key в HTML/APK/Git.

## Настройка backend
1. Создайте Supabase project.
2. Выполните backend/supabase-schema.sql в SQL Editor.
3. В Authentication включите Email, настройте подтверждение и SMTP.
4. Для входа по телефону настройте Phone provider и SMS-провайдера.
5. Для клиента используйте только URL проекта и публичный anon/publishable key. Service-role key никогда не помещайте в клиент.
6. Перед публичным запуском проверьте RLS, подтверждение контактов, восстановление пароля, лимиты Auth и сценарии приглашения в чат.

## Владелец и безопасность
Создайте владельца через штатную регистрацию. Админ-права назначайте серверной миграцией/функцией после проверки auth user ID, а не проверкой email на клиенте. Если пароль, отправленный ранее в переписке, где-либо ещё используется, смените его.

## APK
После настройки workflow должен публиковать артефакт FRONTLINE-Messenger-APK. Пока backend не подключён, это APK оболочки с демонстрационным интерфейсом, не полноценный многопользовательский мессенджер.
